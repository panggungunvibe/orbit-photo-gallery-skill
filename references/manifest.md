# 选片清单

保存在相册项目之外的私人工作目录中。相对路径以清单所在目录为基准；绝对路径也可以。以下只展示一个条目的格式，不是可导入的完整相册。正式清单需要 5–10 个含义不同、名称不同且非空的类目，优先 6–8 类，需以真实照片与视觉审阅结果填写。

```json
{
  "categories": [
    {"id":"sea","title":"海景","note":"海水与沿岸的风景。"}
  ],
  "photos": [
    {
      "id":"sea-001",
      "path":"originals/coast.jpg",
      "group":"sea",
      "title":"把光留在海里",
      "description":"水面上有细碎的光，近岸的颜色浅一些，远处慢慢深下去。今天在这里站了一会儿，想把这片蓝留给以后再看的自己。",
      "alt":"岸边草木与清澈海水",
      "cover":true
    }
  ]
}
```

ID 仅允许小写字母、数字和连字符，最长 64 字符。每张照片一个条目、一个 group；每类非空且最多一个 cover。没指定封面时用第一张。`year` 可选，只在有可靠依据时填写。

可选 `crop: [left, top, right, bottom]` 为 EXIF 校正后图片的归一化坐标（0–1），例如 `[0.25,0,0.7,1]`。必须先目视检查，裁切结果也必须为竖幅。全身人物、多人合照不宜自动居中裁切。

脚本会拒绝相同解码像素的重复文件，即使文件名或裁切不同。近似连拍、缩放副本、带文字注释的副本和拼图需要人工比较。脚本不会自动删原片，导入失败也不会留下部分相册数据。成功导入会替换 `src/artworks.js` 与 `src/categories.js`，旧导出图片不会自动删除。

`public/photos/` 默认被 Git 忽略，防止模板开发中误提交私人素材。若用户明确要公开个人相册，需要自行审核照片和文案，并选择发布方式；不要为了让 Git 收录而自动取消忽略规则。

生成工程前先执行 `python scripts/import_photos.py selection.json --check`。预检不要求已有项目，不写入工程文件；少于五类、超过十类、空类、同名类、精确重复或未裁切横图会失败。预检不会判断语义类别是否是在凑数，智能体必须先完成视觉判断。
